- **Workflow** (minimum scrum, in every issue): Refine → Develop (agent A, branch `claude/issue-<n>` or the run's assigned push branch, PR titled `(#<n>)` with `Closes #<n>` in the body — `Part of #<n>` instead when part of the issue is deferred, or GitHub closes it early. **A closing keyword next to an issue reference closes that issue wherever it sits in the body — including inside a sentence denying it (#144).** "Left open so merging this does not close #<n>" is how PR #139 shut issue 44 while explaining that it must not: GitHub scans the whole body for `close`/`fix`/`resolve` and their forms followed by `#<n>` or the issue's URL, and has no notion of negation, quotation or context. Say "the issue stays open" instead; break the link (`#&#8203;<n>`, or "issue 44" in words) when the keyword is unavoidable; and check what you actually wrote with `node scripts/review-gate.mjs body.md`, which prints the issues that body would close.) → Review (a *different* agent) → QA (the reviewer, e2e + screenshots — **mobile by default, the project CI runs on a PR; the full matrix is the nightly's**, #141, and **CI runs e2e on a PR only when the diff can reach the game**, #176 — every PR still gets a `CI` check, so a missing one is never expected) → Owner action → Done (merged, issue closed).
